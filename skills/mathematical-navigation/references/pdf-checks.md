# PDF の構造・描画・操作を確認する

この手順は [mathematical-navigation](../SKILL.md) が所有する。
`labo-build` と `reading-book` のビルドは同じ検査コードを呼ぶが、出力先と保存境界は
それぞれの契約を保つ。読書レビューは構造検査を利用し、内容・出典・読みやすさを別に確認する。

## 三種類の証拠

| 証拠 | 確認すること | それだけでは確認できないこと |
| --- | --- | --- |
| 構造検査 | 実 PDF の注釈、内部宛先、しおり、指定された期待経路 | 本文の意味、索引の網羅性、見た目、ビューアの動作 |
| 描画確認 | 字形、色、番号、改行、重なり、クリック領域と表示の対応、着地点の内容 | 実際のクリック操作、外部資料の内容 |
| ビューア操作 | 代表経路のクリック、戻る操作、ビューア固有の挙動 | 未確認経路の意味、数学や出典の正しさ |

組版成功とは別に記録する。完全な視覚レビューには全ページの確認が必要であり、
一部だけを見た場合は対象ページと範囲を明記する。機械検査の全件処理を全ページの
視覚確認と呼ばない。

## 毎ビルドの構造検査

索引・参照が更新された現行 PDF を対象に、`scripts/check_pdf.py` を実行する。
Python 標準ライブラリと `qpdf` を使い、PDF を変更せずオフラインで検査する。
解決済みリンクだけを返す高水準 API の件数を母数にせず、実 PDF の `/Annots` にある
リンクの `/A`・`/Dest`、名前付き宛先、しおりを列挙する。解決できない宛先や未対応の
アクションも記録し、読み飛ばしたリンクを成功扱いにしない。

- 内部宛先の解決、参照するページ、リンク領域、しおりの構造を調べ、問題のページと
  対象を報告する。ページ回転や表示領域を考慮し、座標だけから意味の正しさを判定しない。
- 自作文書の `--aux` は一般的な hyperref の `\newlabel` 形式から期待する宛先を
  読み取る補助である。TeX を実行せず、任意のマクロやすべての参照方式を解釈したと
  主張しない。PDF 内の宛先との一致は、必要な本文参照や索引項目の存在まで保証しない。
- 必要な宛先・経路は、文書側の登録元に基づく `--expect` で照合できる。
  PDF に存在するリンクだけから期待経路を逆算すると、丸ごと欠けた経路を見逃す。
  自作文書で目次・しおり・索引・往復経路が要求されている場合は、必要条件を
  本文入口と同じ場所の `<entry>.navigation.json` に記すか、既存の登録元から生成する。
  `main.tex` なら `main.navigation.json` である。通常ビルドがこのファイルを読み込む。
  登録内容を別の手書き一覧へ二重管理せず、意味上の網羅性と必要経路を区別する。
  本文の定義・記法・式と索引の網羅性は [登録規則](document-navigation.md) で別に確認する。
- URL、`GoToR`、`Launch` などの外部経路は一覧化に留め、検査コードから開いたり
  実行したりしない。外部参照の利用可能性と意味の照合は後述の別作業である。

レポートには対象 PDF の識別情報、件数、所見、構造検査の `pass`・`fail`・`incomplete`、
ページごとのリンク・宛先・しおりの比較情報を残す。`pass` は実施した構造検査の範囲に
限られる。検査の未実行・失敗・未対応、必要な入力や実行環境の不足を隠さず、
リンク確認済みとは記さない。構造検査の問題だけで完成した PDF を破棄したり、
影響のない執筆まで停止したりしない。問題の修正と、進められる制作を区別する。

## 呼び出しと保存

スキルの実ディレクトリから `scripts/check_pdf.py` を解決する。基本形は次のとおり。

```sh
python3 <navigation-skill>/scripts/check_pdf.py <current.pdf> --report <cache>/navigation-main.json
```

必要に応じて `--aux <current.aux>`、`--expect <expectations.json>`、
`--previous <prior-report.json>` を加える。`--render-dir <cache>/navigation-render`
は `pdftoppm` によるページ画像とハッシュを生成し、`--dpi 96` で解像度を指定できる。
引数と期待経路の入力形式はスクリプトの `--help` を参照する。
通常ビルドは正本の TeX 入口を `document_source` として記録する。手動検査では
`--source <entry.tex>` でも指定でき、入口が異なる記録との構造・画像比較は行わない。
`--previous` がなければ既存の同名レポートを比較に使う。画像確認を追加する際は、
同名レポートの PDF ハッシュが現物と一致するときだけ、その入口情報を引き継ぐ。
入口が分かれば対応する `.navigation.json` も自動で使う。同じ PDF の既存レポートに
aux の記録があれば、それも再読して検査する。描画を追加しただけで必須経路の失敗を
消さない。明示した `--expect`・`--aux` は自動選択に優先する。
入口情報のない単独 PDF 同士の比較は可能だが、同じ文書かの判断は利用者側に残る。
終了コードは構造検査の通過が `0`、欠陥が `1`、未完了・実行不能が `2`。
URI の構文が通っても外部への到達は未検査であり、外部ファイル操作や未対応アクションは
`incomplete` として残る。しおりやリンクが元からない文書を壊れているとは判定しないため、
必要な経路や最低件数がある場合は期待値を渡す。

例えば、本文の導入先への参照としおりが必要な自作文書では次のように記す。
これは架空の最小例であり、全索引の網羅性を満たす既定値ではない。

```json
{"min_outlines": 1, "routes": [{"label": "def:example"}]}
```

`label` は現行 aux から宛先へ解決する。`from_page` を指定する場合は1始まりの
物理ページ番号であり、改ページ後は再生成する。省略時は全ページからの経路を検索するため、
索引からのリンクと本文中の別リンクを区別するには参照元の指定も必要になる。
通常ビルドは選ばれた TeX 入口に対応する条件だけを使い、別入口の条件へ暗黙に戻らない。
条件がなければ `expectations.status: not_supplied` と明示し、構造の通過を必須経路の
確認済みとしない。不正な設定や読み取り失敗は pass にせず、現行版の所見として報告する。

`labo-build` の結果は既存の `.temp/` 内の `navigation-<stem>.json`、
教材ビルドの結果は `cache/<course>/navigation-main.json` に保存する。
`--render-dir` を使った検査は、同じ場所の `navigation-<stem>.render.json` に
PDF のハッシュ・描画設定・ページ画像のハッシュを別途保存する。次の描画確認はこの基準を
自動で読み込み、構造検査だけの通常ビルドは上書きしない。旧形式の一体型レポートに
描画結果があれば、ビルド時に一度だけ分離して保持する。
現在の構造レポートで `rendering: not_requested` でも、過去の画像比較基準は残る。
基準は過去版の証拠であり、新版の表示確認済みという意味ではない。壊れた基準は使わず、
比較なしで描画する。画像の同一性と、実際に人が確認した範囲は引き続き区別する。
前回との比較は更新前のレポートを用い、同じ文書入口・設定のものかを確認する。
同じ出力名へ別の文書入口を組版できるため、ファイル名だけで前回の証拠を引き継がない。
本文・補助ファイル・期待経路・レポート・ページ画像は文書側の保存境界に従う。
実教材の情報をスキル Git、共有 fixture、CI ログへ取り込まない。

## 内部参照の種類名も確認する

PDF の宛先解決は、表示された「定理」「補題」等と実際の環境種別の一致を保証しない。
[型付き参照](typed-references.md)に従い、共通設定の導入・変更時には共有連番の各環境で
種類名・番号・リンク先を確認する。ラベルの接頭辞だけで環境種別を判定しない。
`cleveref` を使う場合は aux の `@cref` 型情報も照合し、未定義の参照名・型の警告を残さない。
ソースの抽出は候補発見であり、独自マクロ・特殊ラベルを解釈できなければ未確認と記す。
共通設定は小さな例で種類変更・並べ替えへの追従を確認し、対象文書では型ごとの代表参照と
変更による表示の影響を確認する。全リンクの手動操作や数学の全証明再点検は追加しない。

## 差分から再確認範囲を決める

安価な構造検査は毎回全体に行い、前回との差分は描画と操作の再確認対象を選ぶために使う。
リンク・宛先・しおりに差分がないことは、本文の描画が変わっていない証拠ではない。
ソースの変更行だけでページを絞らず、改ページ、索引更新、共通スタイル変更の影響も含める。

実ページの描画差分は、同じレンダラー・版・解像度などの設定で生成した画像のハッシュを
比較して判断する。設定が違う、前回画像の証拠がない、描画していない場合は「不変」と
しない。既に視覚確認済みで同条件の画像が同一のページは、その確認範囲を引き継げる。
未確認ページは差分がなくても未確認のままである。
同一 PDF・同一描画設定で前回の画像ファイルとハッシュを確認できる場合は、画像生成自体も
再利用する。自動ビルドは構造検査だけを行い、画像生成と GUI 操作は毎回自動起動しない。

初回は定理・式・Step・索引・目次・しおりなど実際に使う種類から代表経路を選び、
クリック領域と着地点、必要な戻り経路をビューアで確認する。修正後は変更した経路、
その参照元と宛先、関連するしおりや索引を再確認する。共通リンク設定・PDF 生成系・
ビューアを変えた場合や、構造と表示が食い違う場合は代表経路も取り直す。
同じ PDF・環境・確認範囲の操作を根拠なく繰り返さない。

外部論文・コードは、必要なときに実際の版・節・関数・行への到達を別途確認する。
HTTP 成功やホームページへの到達だけでは足りない。リンク変更や内容・版の更新で
既存の照合が使えなくなった範囲を再確認し、未アクセスや非対応アンカーは記録する。
ファイル・添付は配布時の配置で利用可能か確認し、著者の絶対パスだけで成功としない。

## 終了と引継ぎ

確認前に対象と必要な経路を定め、所見をまとめて修正した後は変更と依存範囲を再確認する。
新しい重大な問題が出ればその問題と影響先を修正・確認し、理由なく全体のクリックや
レビューを初めから繰り返さない。[R30](../../reading-reference/references/review.md) の
終了規則に従い、既出の重大な所見を修正済み・根拠を示して解消・未解決に整理する。
構造検査の状態、描画確認したページ、操作した経路、外部照合、未確認範囲を既存の進捗に
短く残す。未解決の開示は、要求された動作の確認を免除するものではない。
