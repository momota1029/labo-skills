# 種類名と番号を自動生成する内部参照

定理環境の見出しだけでなく、本文から参照するときの種類名も対象環境から生成する。
文書共通設定を正本とし、ラベル接頭辞や本文の文字列へ種類名を重複管理しない。
投稿先の指定クラス・原文表示を尊重し、パッケージを変更できない場合は同じ性質を持つ
既存機構を使う。対応できない制約と未適用範囲は明記する。

## TeX の標準方針

- `cleveref` の `\cref` / `\Cref` 等を使い、日本語名を共通設定する。
  `hyperref` との読込順・定理環境の定義順を実際のクラスで確認する。
  種類名もリンクに含めるなら `nameinlink` を使い、リンク色は既存設定を保つ。
- 定理・補題・命題等が同じ番号カウンタを共有しても、参照の型は環境ごとに分ける。
  `amsthm` と `aliascnt` を使う基本形は次のとおり。全環境を「定理」へ別名指定して解決しない。

```tex
% amsthm, hyperref を読み込んだ後、以下の環境を定義する。
\usepackage{aliascnt}
\usepackage[nameinlink]{cleveref}
\newtheorem{theorem}{定理}[section]
\newaliascnt{lemma}{theorem}
\newtheorem{lemma}[lemma]{補題}
\aliascntresetthe{lemma}
\crefname{theorem}{\mbox{定理}}{\mbox{定理}}
\Crefname{theorem}{\mbox{定理}}{\mbox{定理}}
\crefname{lemma}{\mbox{補題}}{\mbox{補題}}
\Crefname{lemma}{\mbox{補題}}{\mbox{補題}}
```

和文の種類名が途中で折り返されないよう、例では名前を `\mbox` でまとめている。
命題・系・定義・公理・例・演習も、共有連番なら各型のalias counterと名前を定義する。
定理スタイルは既存方針を保持する。長大教材の新規設定は節ごとのリセットとし、
数式も `\numberwithin{equation}{section}` にする。稼働中の既存稿は本文所有者が移行する。章・節・図・表・式・証明Stepなど
実際に参照する型の名称も設定する。articleのようにchapterがないクラスでは適切な親番号にする。
独自クラスで既に環境を定義している場合は、この例を重複定義せずクラスの機構と調整する。

実行できる架空例は [typed-reference-example.tex](../assets/typed-reference-example.tex)。
共有連番と実際の環境種別を扱う例であり、実文書のラベル・設定をコピーしたものではない。

## 既存稿の移行

1. 実際の入口と入力ファイル、共通の定理環境、既存の参照マクロを確認する。
   `定理\ref{...}`、`補題\ref*{...}`、`\hyperref[...]{補題\ref*{...}}` 等を候補として集める。
2. 自作文書の内部参照か、原著の番号・引用文・単なる定理名かを判断する。
   内部の種類名付き参照は原則 `\cref{...}` へ置き換える。リンクを二重に包まない。
   番号のみの参照、`\eqref`、頁参照、原著の「命題2.4」等は用途を保つ。
3. ラベル名と本文の数学を保ち、実環境に型を結び付ける。`prop:` と命名された定理も
   実環境がtheoremなら「定理」と表示する。接頭辞から種類を推測するマクロにしない。
4. 参照名設定・各環境の型情報・既存の連番とリセットを確認する。索引の登録先ラベルを
   勝手に改名しない。アンカー名が変わった場合は aux・期待経路を正規の生成手順で更新する。
5. 通常ビルドで参照と索引を更新し、残る手書き参照候補・未定義参照・未定義型名の警告を確認する。
   残存候補に正当な用途があれば、その範囲を記す。抽出だけで機械的に置換しない。

## 確認と証拠の引継ぎ

共通設定の導入時は小さな例で、異なる環境が同じ連番を使っても各日本語名になること、
環境の並べ替えで番号が変わること、種類変更でラベル名を変えず参照名が変わることを確かめる。
aux の `@cref` 型情報、PDF表示、代表リンクの宛先を対応づける。通常のPDF構造検査だけで
参照名の正しさを確認済みとしない。文字抽出だけでは色やリンク領域の表示を確認できない。

実教材では共通設定と影響する参照・ページを確認し、既存の数学確認は内容と前提が不変なら
引き継ぐ。共通リンク設定を変更した際の代表経路・表示確認は既存のPDF手順に従う。
以後は新規の型・参照マクロ、環境種別変更や不具合がある範囲を確認し、毎回の全件クリックにしない。
