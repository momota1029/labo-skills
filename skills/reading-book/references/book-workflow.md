# 本から講義へ

## 三つの識別層

- **資料**：書名・著者・巻・版・ファイルのハッシュ、印刷頁と PDF 頁の対応を `materials/sources/` に記録する。主資料・補助資料の役割を明記する。資料の記述を移すときは、組み合わさった定義、仮定、量化子、証明の依存を実ページで確認する。
- **数学**：資料や講義章番号に依存しない安定 ID を定義・主張・証明に付ける。`materials/catalog/` は ID、正確な正本文位置、資料上の根拠、直接の前提、確認範囲と改訂、未解決を指す台帳である。本文の証明を台帳に複製しない。同名でも仮定や結論が異なる主張は別 ID とし、同じ主張の別証明は区別する。
- **講義**：`materials/courses/<course>/plan.md` に読者の前提、学習順序、各節の役割、主資料の流れと補助資料の位置を記す。共有数学を `materials/shared/` に昇格させるのは、複数の講義で実際に同じ正確な主張・証明を使うときだけ。単なる似た説明はそれぞれの講義で扱う。

資料の順に盲従せず、問いから定義、具体例、定理、証明、応用へつながる説明を保つ。異なる資料を接ぐ箇所では、同じ語の定義域や完備性、可測性、零集合、量化子、結論の強さを実際に照合する。採用した修正版と原著の差を台帳で区別する。

## 節単位の制作

別担当への依頼、訂正の反映、本文担当の交代は[制作と引継ぎの契約](production-handoff.md)に従う。
進捗の現在要約と対象章の記録から再開し、過去ログ全体の通読を前提にしない。
確定した訂正を現行正本へ戻し、本文・参照・索引の整合が取れた変更をまとめて出力する。
小さな追記のたびに組版・描画・同期確認の一巡を挟まず、既存証拠と変更の影響から
必要な確認を選ぶ。途中版の提示を求められた場合も、正本との対応が分かる出力を渡す。

初稿から[証明の段階](../../mathematical-exposition/references/mathematical-substance.md#初稿から証明の段階を設計する)と
[mathematical-navigation](../../mathematical-navigation/SKILL.md) に従う番号・参照・索引を
本文と一緒に作る。定義・記法・式の導入時に索引を登録し、章末での後付けにしない。
workspace の著者方針と対象の最新指示にある継続的な要件を確認する。

一節から数節を扱う。必要な原著ページと直接の前提を読み、本文の定義・記号・主張・証明・例・演習を完成させながら、**すべての数学**を自分で点検する。抽象的な主張には適切な具体例を与え、核心的な構成や中間計算を省かない。実際に証明していない箇所は確認済みと記さない。

疑問の残る一つの式・補題・段階には、必要に応じて[Lean の局所検査](lean-checks.md)を
使う。短時間で確認して本文へ戻し、一時コードは結果記録後に破棄できる。検査のために
別の恒久的な形式化教材を作らず、機械検査の範囲と本文の自己点検・独立確認を区別する。

`progress.md` には現在の節、完成した本文と数学確認の範囲、原著照合の範囲、未解決、次の実作業、ビルド・表示確認を簡潔に残す。現状の要約を過去の作業履歴と分け、解消した項目を現在の残作業として残さない。大冊では章ごとの記録へリンクし、上位は短くする。資料の版または本文の数学的内容を変更したら、その ID と利用先への影響を調べ、再確認が必要な範囲と従来の確認を引き継ぐ範囲を分ける。直接・間接の利用箇所を一律に未確認へ戻さない。別講義で新たに再利用するときも適用条件を確認する。文章だけの修正なら局所確認でよい。

再開や移行では、最新のユーザー合意と進捗を、実際の本文・入力章・出力へ対応づける。古い入口に残る未着手・完成・全体構想の記述で現在の状態を上書きしない。未確認草稿は保存し、以前の確認済み版と現在の draft 出力を区別する。新しい保存先の指示と現行の制作範囲を入口へ反映し、移行だけを理由に追加執筆しない。

節を束ねたときは参照、用語、記号、依存順序、組版をまとめて確認する。独立した数学確認は、基礎結果、利用先の多い結果、原著の修正、一般化、複数資料の接合を優先する。毎定理の承認待ちにしない。正しさと読者が追える詳しさを別々に確認し、修正した結果の後続適用も点検する。章数、式の数、組版成功を完成の根拠にしない。

PDF の検査方法は [mathematical-navigation の共通手順](../../mathematical-navigation/references/pdf-checks.md)
に従う。毎ビルドの全体構造検査に加え、必要な経路を本文・索引登録と照合する。
描画したページと代表経路のビューア操作を別に記録し、修正後は実際の描画差分と
リンク・しおりの影響範囲を再確認する。同じ GUI 操作を繰り返すことを制作の関門にしない。
本文を読んで行う定義・記法・式の索引網羅性確認は、リンク検査の成功で置き換えない。

ページ画像や OCR は資料のハッシュごとにキャッシュし、同じ版は繰り返し全冊処理しない。入力版・対象節・参照した台帳 ID と改訂を進捗に残し、次回は差分だけを読んでビルドする。読者用 PDF には完成した本文だけを収録し、未完成の目次や概説を完成章として扱わない。

## 章・講義の完了判定

区切りでは、最新の合意範囲と原著の対象単位を、既存の計画・範囲の対応記録から
現行本文へ照合する。残る必須作業は、対象の節・主張 ID・出力位置と、解消を判断する
根拠を付けた個別の項目として既存の進捗へまとめる。本文、証明、原著照合、索引と
表示・操作の必要範囲を落とさず、予定や見出しだけを実施済みの証拠にしない。
独立確認は上記の選択基準で対象と未実施範囲を明示し、全定理の独立確認を暗黙の
完了条件にしない。

確認と修正の一巡は [R30](../../reading-reference/references/review.md) に従って閉じる。
既出の重大な所見を修正済み・根拠を示して解消・未解決に整理し、必須作業や重大な
未解決が残る範囲を制作完了とは記さない。確認の一巡が終了したことと、合意範囲の
制作が完了したことを現状要約で区別する。新しい変更や所見では、その対象と依存・
表示への影響範囲を再確認し、無関係な完了範囲まで再確認対象に戻さない。
