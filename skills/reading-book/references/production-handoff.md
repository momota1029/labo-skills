# 長大教材の制作・訂正・引継ぎ

この契約は `reading-book` と二つの教材確認スキルの共通規則である。
正本と出力の既存配置を維持し、教材を新たな `reading/` へ移さない。
教材の依頼・版・所見は[教材の保存境界](storage.md)の内側に置く。
スキル側には実教材・原著・進捗を保存しない。

## 担当と書込範囲

| 担当 | 書込範囲 | 返すもの |
| --- | --- | --- |
| 本文制作・統合 | 正本 TeX、統合進捗、公式ビルド、共通キャッシュ、公式 PDF・SyncTeX | 本文・出力への反映と次の実作業 |
| 数学確認 | 割り当てられた依頼専用の結果領域 | 確認範囲、欠陥、訂正の要件、影響先 |
| 索引・PDF確認 | 割り当てられた依頼専用の結果・検査領域 | 索引・表示・経路の所見と必要な修正 |

正本の編集者は一人とし、担当名またはスレッド識別子を現在要約に記す。
各依頼に重ならない保存先を指定する。確認担当は共通キャッシュ・統合進捗・公式出力へ
書き込まない。派生画像・検査報告・一時ファイルも自分の依頼領域へ出す。
参照先の汎用スキルが通常ビルドや既定レポートへの保存を説明していても、この担当権限を広げない。
必要な入力が不足すれば対象だけを未確認として返し、担当権限を越えて再生成しない。

これらは担当規則であり、OS のロックやアクセス制限を自動で設定するものではない。
ホストが対応する場合は読取制限も利用する。別担当を利用できない場合は本文担当が
許可された制作・自己点検を進め、独立確認の未実施範囲を記す。役割名を変えただけで
自己点検を独立確認にしない。

## 固定版を渡す

本文担当は既存の章・節の記録を使い、次の小さな依頼情報を渡す。

- 依頼 ID、担当、統合する本文担当、読取対象と専用の書込先。
- 確認する問い、原著・計画上の範囲、対象の安定ラベル、直接の前提と必要な使用先。
- 固定版の場所と識別情報。未コミット変更を含む実ファイルのハッシュなどを使い、
  commit ID だけで作業中の内容を識別したとしない。
- 出力確認では同じ版の PDF、必要な TeX・設定・索引登録・生成索引・aux・期待経路・既存証拠。
  PDF・SyncTeX の対応と確認済み範囲を示す。不足資料は明記する。

固定版はコピーまたは不変の保存版を使い、編集中のファイルへの参照だけで代用しない。
対象と必要な前提を揃え、全冊・全履歴の複製や再読を既定にしない。
未完のビルド途中の入力と出力を混ぜず、対応が確定してから依頼を渡す。
数学の独立確認には、新しい文脈へ正確な主張・証明・許可資料を渡す。
本文担当の議論や他担当の結論を独立確認の読取資料に混ぜない。
変更影響の整理と独立した証明確認を区別し、必要なら別の依頼として扱う。

## 所見の返却と正本への反映

各所見には ID、対象版・ラベル・位置、問題と根拠、訂正案または必要条件、影響先、
再確認箇所と理由、引き継げる確認と根拠を付ける。依頼全体の確認済み範囲と対象外も記す。
所見がないことを全教材の正しさと同一視しない。未確認と欠陥を区別する。

報告は訂正と再開に必要な短さに保つ。対象版・共通前提は冒頭の依頼情報を参照し、
各所見へ同じハッシュ・権限説明・一般的な検査手順を繰り返さない。
関連する所見はまとめ、詳細な機械出力や描画証拠はファイルへの参照で渡す。
対象外は誤解を防ぐために必要な範囲だけ記し、毎回全種類の未実施作業を列挙しない。

本文担当は所見を現行版に照合し、既に解消・引き続き該当・他の変更と競合、を判断する。
旧版への差分を機械的に上書きせず、必要な訂正を現在の正本へ統合する。
数学確認担当の訂正の要件に対する証明作成は本文担当が行う。
未解決の主張は未解決と記録し、その主張に依存しない制作を続ける。

既存の章記録に次の状態を保持し、同じ内容の台帳を増やさない。

| 記録する状態 | 根拠 |
| --- | --- |
| 訂正案あり | 所見 ID と対象版 |
| 正本文へ反映済み | 反映先ラベルと反映後の版 |
| 必要な再確認 | 対象・理由・未了／実施済み・実施者・結果。自己点検と独立確認を区別 |
| PDFへ反映済み | 対応する出力版と反映範囲。表示確認済みという意味にはしない |
| 不採用・既に解消 | 現行本文に基づく理由と根拠 |

これらは別々の状態であり、訂正案の返却や組版成功だけで全項目を完了にしない。
採用した所見は正本への反映・必要な再確認・出力への反映まで追跡する。
確認待ちを一括の承認待ちにせず、具体的な欠陥の影響する部分を扱う。

## 更新と再確認の判断

時間や項目数で停止・許可待ちを設けない。整合する訂正が確定すれば正本へ反映し、
同じ定義・証明に関係する訂正はまとめる。本文・参照・索引が整った変更を出力へ戻す。
単独の式や索引の追加ごとに確認工程を一巡させない。全担当の終了も待たない。
途中版を求められたら現在の正本を出力し、ビルド失敗時は最後の成功版と未反映差分を明示する。
公式 PDF と SyncTeX は同じビルドの組を保持する。移動後の同期は既存ビルド規則に従う。

| 変更 | 再確認の判断 |
| --- | --- |
| 誤字・文章表現 | 該当文の意味が保たれるか。数学的内容が不変なら証明の確認を引き継ぐ |
| 主張・仮定が同じ証明の訂正 | 訂正段階と前後の論理。後続が証明中の構成も使うならそこへ広げる |
| 定理の仮定・結論 | 本体と変更した条件に依存する使用先。影響が伝わる範囲を追う |
| 定義・記法・原著の解釈 | 意味が変わる使用先を調べる。関連しない確認まで取り消さない |
| 改ページ・索引・共通書式 | 影響する表示・参照経路。数学の確認とは分ける |

差分がない本文でも前提が変われば影響を調べる。ファイル全体のハッシュ変更だけで
全件再確認とせず、ラベルと意味で範囲を特定する。影響が不明な箇所は未確認として残す。
原著対応、数学、索引網羅性、構造、表示、操作・同期の証拠はそれぞれ対象版と範囲を持つ。
証拠を引き継ぐ根拠は種類ごとに示す。描画・操作の再確認は
[共通 PDF 手順](../../mathematical-navigation/references/pdf-checks.md)に従い、
本文不変や同じ頁数だけで表示不変を主張しない。全体構造検査は通常ビルドに含める。

## 本文担当の再開・交代

`progress.md` 等の既存の現在要約に、合意範囲、編集担当と対象節、完了範囲と根拠、
具体的残件と解消条件、依頼・返却・反映の状況、正本と最新 PDF の対応、未出力変更、
次の具体的な編集をまとめる。詳細は対象章の記録へリンクし、履歴と現在状態を分ける。
再開時は現在要約と対象章・直接の前提を読み、旧ログの通読や全冊再点検から始めない。

交代時は旧担当の書込と実行中ビルドが止まったことを確認し、編集担当を引き渡す。
旧担当の停止が確かでなければ新担当は正本を書き換えず、読取作業を進める。
受領待ちの所見と固定版も引き継ぎ、古い担当名だけを理由に捨てない。
所要時間を記録する場合は実測の工程時間だけを短く記し、停止条件や固定配分にしない。
