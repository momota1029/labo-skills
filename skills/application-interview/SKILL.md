# Build application documents from confirmed information

Before substantive work, follow [eligibility and handoff](../research-router/references/editing-capability.md).

Use for a request to create, edit, fill or continue an application document.
For a narrow edit, stay within that edit instead of starting a full interview.
Read any supplied document or template before asking the user to transcribe it.
Use the requested target and format; if they are missing and affect the next
step, ask one short question.

## Ask only for useful missing information

Establish the document's purpose, audience and actual requirements from the
request and available material. Reuse information the user already supplied.
Ask one manageable question at a time, normally about one topic. Accept rough
dates, fragments and uncertainty, and turn confirmed answers into draft text
as the conversation proceeds. Do not require the user to know the form's full
structure before beginning.

Prefill facts only from material relevant to this document or from the user's
statements. Do not search unrelated personal files for a profile. Distinguish
confirmed facts from candidates, conflicts, unknowns and deferred answers. A
missing fact in an old CV is not evidence that the event never happened.

For grants and formal applications, identify the exact program, cycle, form
version and instructions. Check current requirements against the official
call or supplied materials. Keep deadlines, eligibility, length limits, budget
rules and required attachments marked unverified when evidence is missing.
Separate completed work, preliminary evidence, hypotheses and future plans.

## Protect factual accuracy and personal information

Never invent dates, positions, degrees, publications, awards, funding,
collaborator consent, approvals, results or commitments. Preserve the status
distinctions between planned, submitted, accepted, published and completed.
Use a clear placeholder or omit unsupported claims, and identify what needs
checking.

Use only personal information needed for the requested document. Do not expose
private details in unrelated files or shared records. Editing a document does
not authorize emailing, submitting, publishing or committing it. Before
delivery, check the actual form requirements, factual consistency, remaining
placeholders, arithmetic where relevant, and the rendered output when the
requested format can be inspected.

When a user wants to pause, show the current draft or continue later, preserve
the useful decisions and open questions in the requested document or session
location. If no more questions are wanted, draft from the available evidence
and make the remaining gaps visible.
