# Request and next-action consultation

For each request, check the intended artifact, scope, constraints and next action.
When a separate advisor is callable and delegation is permitted, send that short
packet under the [invocation contract](subagent-invocation.md) and read its reply
before substantive work. A named advisor preset is not required: a general-purpose
worker can take this bounded role. Reading sources to understand the request may
come first. Reuse the check when the same assignment passes between skills.

## When separate consultation is unavailable

Use the actual host tools, not another host's bundled role files, to establish
availability. If delegation is absent, disabled, exhausted or fails, record that
independent consultation was not performed. Briefly check the scope and next action
yourself, then continue authorized work under the
[assignment rule](editing-capability.md). Do not install roles, request a particular
model, retry an unavailable preset repeatedly, or ask the user to repair host setup
merely to begin ordinary drafting. An available native default or inherited selection
is valid; hidden model/effort metadata is not a blocker.

This fallback is a local scope check, not an independent consultation. Do not invent
an advisor response. It does not waive an explicitly required independent review,
user approval, read-only restriction or a concrete missing source/tool/proof obligation.
Hold only the affected decision and continue independent work that is authorized.

## Advisor responsibility

Check the request and evidence rather than echoing the coordinator's plan. Return
brief agreement or a concrete mismatch and correction. Do not add unrelated work or
judge eligibility by a model name. This checks the plan, not mathematical correctness
or permission to exceed the user's scope. Advisors and delegated workers do not
recursively commission another advisor for the same assignment.
